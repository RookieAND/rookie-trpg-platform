# CoC 7판 VTT (개발 중)

명세: Claude Docs "CoC 7판 VTT 서비스 명세서". 지금은 실시간 뼈대, 룸 생성·초대·세션 흐름, 파일 저장까지 구현했습니다.

## 구조

모노레포(pnpm)이고, 프런트는 FSD, 백엔드는 DDD로 나눕니다. 의존 방향은 `pnpm arch`가 검사합니다.

| 경로 | 역할 |
| --- | --- |
| `apps/web` | Next.js 프런트엔드(FSD). `src/app`(라우트, 얇게) → `views` → `widgets` → `features` → `entities` → `shared`. 위 계층만 아래를 가져오고, 다른 슬라이스는 `index.ts`로만 접근 |
| `apps/api` | NestJS 백엔드(DDD). 컨텍스트 `identity`(신원), `room`(룸·초대·실시간), `character`(보관함). 각 컨텍스트는 `domain` ← `application` ← `infrastructure`/`interface`. 구성 루트는 `app.module.ts` |
| `packages/room-core` | 룸 엔진(권한, 보임 범위, 굴림, 시트, 재접속, 일시정지). 네트워크를 모르는 순수 도메인 로직 |
| `packages/shared` | 메시지 규격(zod), 주사위 엔진(BCDice 7판 표기), 시트 모델, 클라이언트 상태 리듀서 |

## 실행

```bash
pnpm install
pnpm dev:api     # http://localhost:8787 (ws: /ws)
pnpm dev:web     # http://localhost:3000
pnpm test        # 단위·통합 테스트
pnpm arch        # 아키텍처 의존 방향 검사
pnpm e2e         # 실제 브라우저 여러 개로 전체 흐름 확인(위 두 서버가 떠 있어야 함)
```

운영 모드로 확인하려면(배포 절차 전체는 [docs/deploy-env.md](docs/deploy-env.md)):

```bash
pnpm build:api && pnpm start:api     # esbuild로 묶은 apps/api/dist/main.js를 node로 실행
node scripts/smoke-prod.mjs          # 빌드한 API를 production 모드로 띄워 로그인·룸·ws·종료·재시작을 점검
pnpm cleanup:images --dry-run        # 쓰이지 않는 이미지·오디오 찾기(빌드 후)
docker build -t coc-vtt-api .        # API 이미지(웹은 Vercel). deploy/에 Fly·Render·Railway 예시
```

## 흐름

1. 로비에서 이름으로 로그인(개발용) → 새 룸을 만들면 만든 사람이 GM이 됩니다.
2. GM이 룸 안의 "초대"로 링크를 만들어 PL에게 보냅니다. 초대 코드가 없으면 처음 오는 사람은 들어올 수 없습니다.
3. 룸은 "대기(IDLE)"에서 시작합니다. GM만 준비할 수 있고, "세션 시작"을 누르면 진행 중이 됩니다.
4. GM은 맵을 "장면"으로 나눠 미리 꾸밀 수 있고(PL에게는 진행 중인 장면만 보임), 컷/페이드로 전환합니다. 핸드아웃은 선택한 PL에게 공개하고 바로 펼쳐 보일 수 있습니다.
5. GM이 나가면 자동 일시정지, 돌아와서 "이어하기"를 누르면 재개합니다. "세션 종료"는 대기로 돌아갑니다.
6. 캐릭터는 로비의 "내 캐릭터"(보관함)에서 만듭니다. 룸의 "시트" 탭에서 불러오면 복사본이 생기고, 시트는 주인과 GM만 봅니다. 세션이 끝나면 "보관함에 반영"으로 HP·SAN·기능·성장 표시를 원본에 되돌립니다.
7. 룸 상태는 `apps/api/data/`에 JSON으로 저장되고 서버를 다시 켜도 이어집니다(진행 중이던 세션은 일시정지로 복원). `DATA_DIR=memory`로 끌 수 있습니다.
8. 세션 종료는 정산 창을 거칩니다. GM이 엔딩 이름, SAN 보상 식(예: 1d6)을 정하고, 성장 표시가 된 기능은 성장 굴림(d100이 현재값보다 크거나 96 이상이면 +1d10)을 합니다. 결과는 모두에게 보입니다.
9. 시트의 "SAN 체크"에 `성공 시/실패 시`(예: 0/1d6)로 손실을 적어 굴립니다. 대실패는 실패 손실의 최댓값, 한 번에 5 이상 잃으면 INT 판정(성공 시 일시적 광기), 하루 손실이 하루 시작 SAN의 1/5 이상이면 장기 광기, SAN 0은 영구 광기로 시트에 표시합니다. "하루 지남"은 GM이 누릅니다. 광기 상태는 GM만 바꾸고, GM이 적어 둔 "광기표"에서 증상과 지속 시간을 굴립니다(증상표는 GM에게만 보이고, 룰북 표는 담지 않았습니다).
10. GM은 룸 안의 "디스코드"에서 채널 웹훅을 연결하면 세션 시작·정지·종료와 공개 굴림이 채널에 올라갑니다(비밀 굴림은 보내지 않고, 웹훅 주소는 저장 뒤 다시 보여 주지 않습니다).
11. 시트에는 무기(공격 기능·피해 식), 소지품, 인물 배경, 상태(중상·기절·죽어감)가 있습니다. 무기의 "공격"은 그 기능으로 판정하고 "피해"는 `1d6+db`처럼 적은 식을 굴려 로그에 남깁니다(db는 STR+SIZ로 계산한 피해 보너스). 상태(중상·기절·빈사·사망)는 피해 적용·회복과 연결되어 자동으로 바뀝니다(46번).
12. 이미지: GM은 선택한 토큰·소품에 "이미지", 장면 막대에서 "배경", 핸드아웃 편집에서 "이미지 넣기"로 PNG/JPG/GIF/WEBP(3MB까지)를 올립니다. 서버는 파일 앞부분으로 형식을 확인하고(SVG는 받지 않음), 사람마다 시간당 30장으로 제한합니다. 개발 기본값은 `data/images` 폴더에 저장하고, 저장소는 `ImageStorage` 포트라서 R2/S3 어댑터로 바꿀 수 있습니다. 이미지 주소는 추측할 수 없는 id라서 보기는 로그인 없이 열리고, 쓰지 않는 파일을 지우는 정리는 아직 없습니다.
13. 시작 장면: GM이 장면 막대에서 "시작 장면으로"를 누르면 ▶ 표시가 붙고, 다음 세션을 시작할 때 그 장면이 컷으로 열립니다. 지정은 GM만 보고 하나만 남습니다. 비트·분기 같은 나머지 세션 흐름은 아직 없습니다.
14. 전투 순서: 룸의 "전투" 탭에서 GM이 "전투 시작"을 누르면 룸의 캐릭터가 시트 DEX 높은 순으로 서고(같은 DEX는 먼저 등록한 쪽이 앞), NPC는 이름과 DEX로 끼워 넣습니다. "다음 차례"로 넘기고 한 바퀴 돌면 라운드가 오르며, 모두가 같은 순서를 봅니다(캐릭터 DEX도 함께 보입니다). 피해 적용은 GM이 누릅니다(46번). 명중 판정 자동화, 총기 DEX +50 등은 하지 않습니다.
15. 저장소: 개발 기본값은 `data/` 폴더의 파일이고, `DATABASE_URL=postgres://...`를 주면 룸·보관함·이미지를 Postgres에 저장합니다(Supabase의 Postgres 주소도 같은 방식). 서버가 켜질 때 테이블이 없으면 만들며(`rooms`, `vaults`, `libraries`, `images`), 서버를 다시 켜도 룸과 이미지가 남는 것을 로컬 Postgres 16으로 확인했습니다. 어댑터 테스트는 `TEST_DATABASE_URL=postgres://... pnpm test`로 켭니다(없으면 건너뜁니다). 실제 Supabase 연결은 하지 않았고, 이미지는 bytea로 저장하므로 트래픽이 커지면 R2/S3 어댑터로 바꿉니다.
16. 세션 흐름(GM 전용 "흐름" 탭): 시나리오를 비트(시작·진행·엔딩)로 짜고, 비트마다 들어갈 때 열 장면과 펼칠 핸드아웃(큐), GM 메모를 정합니다. 비트 사이의 분기는 수동, 판정 결과(기능+단계), 수치 임계(HP·SAN·행운), 핸드아웃 공개 조건을 둘 수 있고, 조건이 맞으면 서버가 GM에게만 "제안"합니다(스스로 옮기지 않고, GM의 비밀 굴림은 쓰지 않습니다). 세션을 시작하면 시작 비트의 큐가 실행되고, 엔딩을 확정하면 종료 창이 엔딩 이름과 SAN 보상으로 미리 채워집니다. 비트별 "자동 실행"은 만들지 않았습니다(기본 꺼짐 상태와 같습니다).
17. 음향(GM 전용 "음향" 탭): GM이 mp3/ogg/wav/m4a(10MB까지)를 배경음(반복) 또는 효과음(한 번)으로 올려 라이브러리에 두고, 재생·정지·볼륨·페이드(없음/1초/3초)를 조절합니다. 소리는 서버가 알려 준 시작 시각 기준으로 모두 같은 자리에서 흐르고(배경음은 늦게 들어와도 지금 소절부터), 참가자는 헤더의 "소리"에서 배경음·효과음·굴림 효과음 볼륨과 전체 음소거를 이 브라우저에 저장해 따로 조절합니다. 굴림 효과음은 파일 없이 합성한 짧은 소리입니다. 음원 이름은 GM만 보고 참가자는 파일 id만 받습니다. 비트 편집의 "들어갈 때 틀 배경음"으로 비트 큐에 묶을 수 있고, 음원을 지우면 연결도 풀립니다. 브라우저 정책상 첫 클릭·키 입력 뒤에야 소리가 나며(헤더 "소리 켜기"로도 가능), 실제 소리는 자동 테스트로 확인하지 못해 재생 상태(DOM)만 검증했습니다. 업로드한 음원 정리와 로컬 파일 외 저장소 어댑터(R2 등)는 이미지와 같은 상태입니다.
18. 장면 묶음: 장면 막대의 "장면 배경음"으로 장면에 라이브러리의 배경음을 묶으면, 그 장면으로 바뀔 때(수동 전환·시작 장면·비트 큐 모두) 함께 틀립니다. 페이드 전환이면 1.5초 페이드이고, 이미 같은 곡이 흐르고 있으면 끊지 않습니다. 맵(배경)·오브젝트 배치·전환 효과(컷/페이드)는 기존 장면 기능을 그대로 쓰며, 배경음 연결은 GM만 알고 음원을 지우면 풀립니다. 전환 효과를 장면에 미리 묶어 두는 것은 하지 않았습니다(전환할 때 컷/페이드를 고릅니다).
19. 로그 내보내기: 룸의 "굴림" 탭에서 "굴림 기록 저장"을 누르면 세션별로 묶은 굴림 기록(시각·이름·캐릭터/기능·식·결과, 비밀·푸시·행운 표시)이 마크다운 파일로 내려옵니다. 서버를 거치지 않고 이 화면이 이미 받은 기록으로 만들기 때문에, 보는 사람이 볼 수 없던 굴림(PL 화면의 GM 비밀 굴림)은 담기지 않고 그 안내가 붙습니다. 화면에는 최근 200건까지만 남아 있어 그보다 오래된 굴림은 파일에도 없으며, 채팅·핸드아웃·시트 변경 이력은 포함하지 않습니다.
20. 매크로: "굴림" 탭의 "매크로 편집"에서 이름과 굴림 식(`1d6+2`, `CC<=60`, `(2d6+6)*5` 등, 47번)을 저장해 두면 버튼 한 번으로 굴립니다. 식은 저장할 때 서버와 같은 규칙으로 미리 확인하고(잘못된 식은 거절), 이름은 20자·개수는 12개까지, 같은 이름은 둘 수 없습니다. GM은 "비밀 굴림으로 굴리기"를 켠 매크로(🔒)를 만들 수 있습니다. 매크로는 사람마다 따로 서버의 "내 서재"에 저장되어 기기를 옮겨도 따라옵니다(23번). 시트 기능 판정은 시트의 굴림 버튼을 그대로 씁니다.
21. 생성 마법사: 내 캐릭터의 "마법사로 만들기"가 7판 규칙대로 네 단계(기본 정보 → 특성치 → 기능 → 확인)로 안내합니다. 특성치는 굴리거나 직접 적고(합계 안내, 포인트 구입은 460), 나이 보정을 적용합니다(15~19세: STR·SIZ 합계 −5·EDU −5·행운 두 번 굴려 높은 쪽 / 40대 이후: STR·CON·DEX에서 −5·−10·−20·−40·−80을 직접 나눠 깎고 APP·교육 향상 판정 횟수도 나이대별로 적용). 교육 향상 판정은 d100이 EDU보다 클 때 1d10을 올립니다. 기능은 직업 포인트(EDU×4 또는 EDU×2+STR/DEX/APP/POW×2 중 선택)와 관심 포인트(INT×2)를 따로 쓰며, 한 기능은 75까지·남는 포인트는 그대로 둘 수 있고, 모국어·크툴루 신화에는 쓸 수 없습니다. 기본 기능에 신용도(0)를 더했습니다. 직업은 이름만 적고 직업별 기능 목록·신용도 범위·직업 포인트 공식은 정해 두지 않았으며(직업 정의는 사용자가 직접 만드는 방침), 기능은 직업 포인트로 쓸 수 있는 목록을 제한하지 않습니다. 기존 "새 캐릭터" 폼은 그대로 있어 만든 뒤 무기·세부를 고칠 수 있습니다.
22. 직업 정의: 내 캐릭터 화면의 "직업 정의하기"에서 직업 이름, 직업 포인트 공식, 신용도 범위(0~99), 직업 기능(12개까지, 신용도는 늘 포함)을 저장해 두면 생성 마법사 첫 단계에서 불러 쓸 수 있습니다. 불러오면 직업 포인트는 직업 기능(★)과 신용도에만 쓸 수 있고 신용도(직업+관심 포인트 합)는 정한 범위 안이어야 다음 단계로 넘어갑니다. 안 고르면 제한이 없습니다. 직업 정의는 사람마다 따로 서버의 "내 서재"에 저장하고(23번), 20개까지, 같은 이름은 둘 수 없습니다. 기본 직업 목록은 넣지 않았습니다(직업 정의는 사용자가 직접 만드는 방침). 대신 정의를 고치고(수정), 파일(JSON)로 내보내고 가져와 GM과 PL이 직업 목록을 나눌 수 있습니다(가져올 때 규칙에 안 맞거나 이름이 겹치는 직업은 건너뜁니다). 마법사 규칙 계산은 `packages/shared/src/creation.ts`에 있어 서버 저장으로 옮길 때 그대로 쓸 수 있습니다.
23. 내 서재(서버 저장): 굴림 매크로와 직업 정의는 `GET/PUT /library`로 서버에 사람별 한 덩어리로 저장합니다(파일은 `data/library`, Postgres는 `libraries` 테이블, 로컬 Postgres 16으로 어댑터 확인). 서버가 매크로 12개·직업 20개·이름 중복·굴림 식·직업 정의 규칙을 다시 검사하고, 저장은 통째로 바꾸되 저장 번호(revision)를 함께 보내, 그 사이 다른 기기가 저장했으면 서버가 409와 최신 서재를 돌려주고 화면이 항목(id) 단위로 합쳐 다시 저장합니다(같은 항목을 둘 다 고쳤으면 내 쪽이 이기고, 이름 중복·개수 한도 때문에 합칠 수 없으면 최신 내용을 불러오고 알립니다). 창으로 돌아올 때도 다른 기기의 변경을 가져옵니다. 화면은 서버에서 불러온 뒤에만 고칠 수 있고(불러오기 전에 빈 값으로 덮어쓰지 않도록), 저장에 실패하면 화면을 되돌리고 알립니다. 이전에 이 브라우저에 저장해 둔 매크로·직업은 서버 서재가 비어 있을 때 처음 접속하면서 한 번 옮기고 브라우저 쪽은 지웁니다.
24. 안개와 시야: GM이 보드 아래 "안개 켜기"를 누르면 그 장면에서 참가자(PL·관전자)에게는 원 밖이 검게 가려집니다. 원은 "영역 밝히기"(반지름을 고르고 보드를 눌러 찍음, 장면당 60개까지, 되돌리기·모두 지우기)와 토큰의 "시야 주기"(반지름 10~600, 토큰이 움직이면 같이 움직임)로 만들며, 모든 참가자가 같은 원을 봅니다(파티 시야). 원 밖의 오브젝트는 서버가 그 사람에게 아예 보내지 않고(움직이거나 시야가 바뀌면 새로 보내거나 지움), 내 토큰은 항상 보이며 GM 전용 오브젝트는 원 안에서도 안 보입니다. GM 화면에는 가려진 곳이 반투명하게 보이고 원 테두리가 점선으로 나옵니다. 지도 배경도 안개에 가려집니다. 벽·조명에 따른 시야 계산은 하지 않았고(원형 반지름만), 한 번 밝힌 곳을 기억해 두는 탐험 기록은 27번에 따로 있습니다. 시야 토큰이 숨겨진 상태여도(GM 전용) 그 둘레는 밝아지므로 필요하면 시야를 주지 마세요.
25. 판정 요청: GM이 "굴림" 탭에서 판정 이름, 난이도, 받을 사람(전원 또는 한 명)을 정해 요청하면 PL 화면에 배너가 뜨고, 배너의 버튼으로 바로 굴립니다.
26. 보드 조작: 확대·축소·이동은 +/− 버튼, 마우스 휠(커서 기준), 두 손가락 모으기, 빈 곳 끌기로 하고 "맞춤"·"내 토큰"으로 돌아옵니다(59번 참고). 내 토큰은 방향키로 움직입니다(60번).
27. 안개 탐험 기록: 안개가 켜진 장면에서 시야 토큰·밝힌 영역이 한 번이라도 비춘 자리를 서버가 장면마다 기록해 두고(최대 200개, 거의 겹치는 원은 합침, 밝힌 영역을 지워도 남음) PL에게는 지금 안 보이지만 가 본 자리를 어둡게 비춰 보여 줍니다. 그 자리의 오브젝트는 지금 시야 밖이면 여전히 보내지 않습니다. GM 화면에는 기록이 점선 고리로 보이고 "탐험 기록 지우기"로 비울 수 있습니다.
28. 시나리오 가져오기: `pnpm import:scenario <시나리오.json> [--user 이름] [--api 주소] [--room 룸이름]`이 시나리오 파일(`format: roll-and-call-scenario`)을 GM이 만든 것처럼 룸 하나로 옮깁니다(장면·시작 장면, 소품·NPC 토큰, NPC 시트, 핸드아웃, 세션 흐름의 비트·분기). 서버가 켜져 있어야 하고, 개발용 로그인은 이름이 곧 신원이라 같은 이름으로 로비에 들어가면 "내 룸"에 보입니다(운영 로그인은 `--token`). 이 명령은 새 룸을 만들고, 이미 있는 룸에 더하려면 웹의 "시나리오 가져오기"(50번)를 씁니다. 시나리오 파일 자체는 저장소에 넣지 않습니다.
29. 화면 정리(밤의 탁자): Linear·Cursor 계열의 낮은 대비·얇은 선·작은 글자로 디자인 토큰을 다시 잡았습니다(`apps/web/src/app/globals.css`). 버튼이 흩어져 있던 곳은 메뉴로 접었습니다: 룸 헤더는 "초대"와 "세션 시작"만 밖에 두고 효과·소리·판정 효과·광기표·디스코드는 "설정" 메뉴로, 장면 막대의 시작 장면·배경·배경음·이름·삭제는 "장면 설정" 메뉴로 모았습니다. 보드 아래 도구에는 "놓기·안개·단축키" 이름표와 설명(마우스를 올리면 보임)을 달았고, GM이 세션 시작 전에 룸에 들어오면 "장면 꾸미기 → 토큰 놓기 → PL 부르기 → 세션 시작" 체크리스트가 보이며 끝낸 단계는 자동으로 체크됩니다. 받은 뒤 화면이 `Module not found`로 깨지면 새 패키지(폰트)가 설치되지 않은 것이니 `pnpm install`을 먼저 실행하세요.
30. GM 전용 노트: 핸드아웃을 "GM 전용 노트"로 만들면 공개 범위를 바꾸거나 펼쳐 보이거나 비트·분기 조건에 붙일 수 없어 실수로 PL에게 새지 않습니다(서버가 거절). 노트를 일반 초안으로 되돌리려면 편집에서 공개 범위를 바꿉니다. 시나리오 가져오기는 제목이 `[KP]`(또는 `[GM]`)로 시작하는 핸드아웃을 노트로 만들고, 머리말은 제목에서 뗍니다.
31. 룸 삭제: 로비 카드의 "삭제"를 누르고 한 번 더 확인하면 룸 주인이 룸을 지웁니다(`DELETE /rooms/:id`, 주인만). 저장소에서 지우고 붙어 있던 연결은 4404로 끊기며, 대기 중이던 저장이 룸을 되살리지 않습니다. 되돌릴 수 없습니다.
32. 되돌리기(GM): Ctrl+Z(맥은 ⌘+Z) 또는 보드 옆 "↶ 되돌리기" 버튼이 가장 최근 변경을 하나씩 되돌립니다(`undo.last`). 되돌릴 수 있는 것은 토큰·오브젝트의 추가·이동·수정·삭제와 안개 영역 밝히기·지우기·모두 지우기, 탐험 기록 지우기뿐이고, 장면·핸드아웃·시트·세션 흐름 같은 변경은 되돌리지 못합니다. 기록은 서버 메모리에 20개까지만 있어 서버를 다시 켜면 사라지며, 그 뒤 다른 사람이 같은 대상을 바꿨거나 대상이 사라졌으면 "되돌릴 수 없어요"로 알리고 그 기록은 버립니다.
33. 핑: 보드에서 길게 누르기(약 0.55초), Alt+클릭, 빈 곳 더블클릭, 토큰을 고른 채 P 키로 그 자리를 모두에게 가리킵니다(`board.ping`). 핑은 1.8초 동안 파동과 이름표로 보이고 저장하지 않으며, 한 사람당 초당 2번까지입니다. 관전자는 보내지 못하고, 지금 진행 중인 장면에서만 보낼 수 있습니다. 안개가 켜진 장면에서는 GM과 보낸 사람 말고는 그 자리가 시야 원 안일 때만 받아, 안개 속 위치가 새지 않습니다.
34. 전투 차례 표시: 전투 중 지금 차례인 캐릭터의 주인(PL)이 가진 토큰에 점선 링과 "차례" 라벨이 붙고, 내 차례이면 보드 위에 "내 차례예요 · N라운드"가 뜹니다. 차례가 아닌 PL이 자기 토큰을 끌면 "지금은 ○○의 차례예요" 안내가 같은 차례에 한 번만 뜨지만 움직임을 막지는 않습니다(서버도 차례를 검사하지 않음). NPC 칸은 내 차례로 치지 않고, 칸의 캐릭터 주인을 알 수 없으면 강조하지 않습니다.
35. 파티 토큰과 장면 따라오기: 안개 장면에서도 PL이 가진 토큰은 다른 PL에게 늘 보입니다(숨기려면 GM이 그 토큰을 숨깁니다). GM이 다른 장면으로 전환하면 새 장면에 토큰이 없는 PL에게는 이전 장면의 토큰(이름·이미지·시야)을 빈자리에 복사해 주고, 이미 토큰이 있는 PL은 그대로 둡니다. 복사를 끄고 싶으면 장면 막대의 "PL 토큰도 가져가기"를 끄고 전환합니다(기본은 켜짐, 보는 장면이 진행 중이 아닐 때만 보입니다). Ctrl+K 장면 큐는 늘 복사합니다.
36. 음악 정지: 장면 배경음, 비트의 배경음, 장면 막대·흐름 탭의 선택 목록에서 "■ 음악 정지"를 고르면, 그 장면으로 바뀌거나 그 비트에 들어갈 때 흐르던 배경음이 멈춥니다(컷은 0.6초, 페이드 전환은 1.5초에 걸쳐). 아무것도 고르지 않은 것과 달라서, 비워 두면 흐르던 배경음을 그대로 둡니다.
37. 세션 전 시트 글 수정: 세션이 시작되기 전(대기)에도 PL은 시트의 소지품·인물 배경·메모만 미리 채울 수 있습니다. 능력치·HP·판정 같은 수치 변경은 세션이 열려야 하며, 한 번의 수정에 수치가 하나라도 섞이면 통째로 거절됩니다.
38. 이동 잠금: GM의 보드 도구에 있는 "이동 잠금" 버튼은 장면 안에서 주인이 있는 모든 PL 토큰을 한꺼번에 잠그고(`object.update`의 `locked`), 모두 잠긴 상태에서는 "이동 풀기"로 바뀌어 한꺼번에 풉니다. 잠긴 토큰은 주인이 움직일 수 없고(서버도 거절) GM은 그대로 움직일 수 있으며, 토큰 이름 옆에 "잠김"이 붙습니다. 토큰 하나만 잠그는 "잠그기"는 따로 있습니다. 전투 정리나 컷신용이며 PL 토큰이 하나도 없으면 버튼이 꺼집니다.
39. 이동 거리: 토큰·오브젝트를 끄는 동안 출발점에서 현재 위치까지 점선이 그어지고 "N.N칸"이 표시됩니다(1칸 = 격자 40). 직선 거리를 소수 첫째 자리까지 보여 줄 뿐이라 이동력 제한이나 장애물은 따지지 않고, 아주 조금(1/8칸 미만) 움직였을 때는 나타나지 않으며, 이 표시는 끄는 사람 화면에만 보입니다.
40. CSV·구글 시트 가져오기: 내 캐릭터의 "CSV로 내보내기"(카드의 `CSV`, 편집 폼 위)가 UTF-8(BOM 포함, 엑셀에서 한글이 깨지지 않음) 파일을 내려주고, "CSV로 가져오기"가 파일·붙여넣기(구글 시트·엑셀에서 복사한 탭 글도 됨)·구글 시트 링크 어느 쪽이든 같은 미리보기를 거친 뒤에만 적용합니다(보관함은 "새 캐릭터 폼으로 열기", 편집 폼은 "폼에 적용"이고 저장은 따로 누릅니다). 파일 모양은 고정이고 `[기본 정보] [특성치] [파생 수치](HP·MP·SAN·행운의 현재·최대) [기능](이름·값·성장 O) [무기] [소지품] [비고](메모·인물 배경)` 구역으로 나뉘며, 빈 줄과 `#` 줄은 무시합니다. "양식 받기"가 같은 모양의 빈 양식(7판 기본 기능 포함, 이름은 비어 있음)을 줍니다. 값 검사는 서버와 같은 `characterInputSchema`를 쓰고(`packages/shared/src/sheet-csv.ts`), 범위를 벗어난 기능 값·중복·30자 초과·잘못된 무기 피해 식은 그 행만 건너뛰고 행 번호와 함께 보여 주며, 이름·나이·특성치가 틀리면 가져오지 않습니다. 목록에 없는 기능 이름(오타 등)은 알림만 하고 그대로 가져오고, 최대 HP·MP는 특성치로 다시 계산하며(파일의 최대 칸은 참고용), 소지품·메모가 서버 한도를 넘으면 한도까지만 가져옵니다. 엑셀이 EUC-KR로 저장한 파일은 자동으로 알아봅니다. `=`·`+`·`-`·`@`로 시작하는 글은 엑셀 수식으로 읽히지 않도록 내보낼 때 앞에 `'`를 붙이고 가져올 때 뗍니다. 구글 시트는 "링크가 있는 모든 사용자 - 보기"로 공유하거나 웹에 게시한 시트의 링크를 붙이면 서버가 `POST /sheet-import/google`(로그인 필요)로 `docs.google.com/spreadsheets/d/<id>/export?format=csv`(게시 주소는 `pub?output=csv`)를 한 번 받아 와 CSV 글만 돌려줍니다. 허용 주소는 https의 docs.google.com 스프레드시트 두 모양뿐이고(다른 호스트·포트·계정 정보는 거절), 리디렉션은 같은 호스트의 내보내기 주소로만 따라가며(구글 로그인으로 가면 "공유 설정 확인" 안내), 1MB·8초 상한과 사람당 분당 20회 제한이 있고 쿠키·인증 정보는 보내지 않습니다. 이것은 읽기만 하는 한 번 가져오기라서 구글 시트와 계속 동기화되지 않고 시트에 다시 쓰지도 않으며(구글 로그인·OAuth는 없음), 비공개 시트는 가져올 수 없고 시트를 고쳐도 이미 가져온 캐릭터는 바뀌지 않습니다. 룸의 "시트" 탭에서도 "CSV로 가져오기"·"양식 받기"가 있지만 기존 "불러오기"와 같은 권한이라(GM은 언제나, PL은 아직 자기 캐릭터가 없을 때만) 새 시트로 등록할 뿐 이미 있는 시트를 덮어쓰지는 않고, 그 탭의 "CSV로 내보내기"는 지금 보는 시트를 내려받습니다(보관함 저장 때와 달리 성장 표시·현재 HP 등이 그대로 담김). 구글 서버로는 이 개발 환경에서 접속할 수 없어 실제 구글 응답으로는 확인하지 못했고, 가짜 응답(리디렉션·크기·시간 초과 포함)으로 시험했습니다. 구글이 export를 `docs.google.com` 밖(예: googleusercontent.com)으로 리디렉션하는 시트는 허용 목록 때문에 가져오지 못하며, 그때는 시트를 "파일 > 다운로드 > CSV"로 받아 파일로 가져오면 됩니다. 시트 화면도 "기본 정보 / 파생 수치 / 특성치 / 무기 / 기능 / 소지품 / 비고" 묶음(제목을 눌러 접기)으로 정리했고, 기능은 이름 찾기와 "수정한 기능만 보기"(초기값에서 값이 바뀌었거나 성장 표시가 있거나 목록에 없는 기능)로 줄여 볼 수 있습니다.
41. 비밀 보호(NPC 시트·숨긴 토큰): GM이 만든 시트(주인이 PL이 아닌 시트)는 NPC 시트로 봅니다. 전투를 시작하면 NPC 시트의 칸은 GM에게만 이름·DEX가 가고, PL·관전자에게는 "알 수 없는 상대"(DEX ?, `hidden: true`)로 자리만 보냅니다(순서와 차례 위치는 그대로). GM이 "NPC 추가"로 직접 적어 넣은 칸은 공개하겠다는 뜻이라 그대로 보입니다. 세션 종료 정산의 SAN 보상·성장 기록도 NPC 시트 몫은 GM에게만 가고 PL·관전자 요약에서는 빠집니다. 숨긴 토큰(GM 층이거나 일부에게만 공개)에 시야를 줘도 그 원은 PL에게 보내지 않아 안개 속 위치가 새지 않습니다(밝히려면 먼저 토큰을 공개합니다).
42. 새 토큰 소유자 기본값은 "소유자 없음(NPC)"입니다. 이름을 비워도 PL 이름이 붙지 않고("토큰N"), PL은 소유자 없는 토큰을 움직일 수 없습니다.
43. 시트 글칸(소지품·인물 배경·메모)은 입력 중에 HP 변경 같은 다른 변경이 도착해도 쓰던 글을 지키고, 칸을 벗어날 때 합쳐 저장합니다. HP·MP·SAN·행운은 ±1, ±5 버튼과 직접 입력(`12` 그 값으로, `+3`·`-7` 더하고 빼기, Enter)으로 바꿉니다(0~최대로 맞춤).
44. 막힌 버튼의 이유: 굴리기(세션 전·일시정지), 마법사 "다음", 로그인 "시작하기", 핸드아웃 "펼쳐 보이기"는 옆이나 아래에 이유 한 줄이 붙고 `aria-describedby`로 이어집니다. 초안 핸드아웃에는 "공개하기"가 있어 한 번에 전원 공개와 펼쳐 보이기를 합니다(`handout.show`의 `reveal`).
45. 화면 안 확인 창: 룸 안의 `window.confirm`/`prompt`를 모두 `shared/ui`의 `useAsk`(초점 가두기·Esc 취소)로 바꿨습니다. 조사가 달라지는 이름은 `josa(word, "을/를")`(`packages/shared/src/josa.ts`)로 붙입니다. 시트에서 굴린 결과는 오른쪽 탭을 옮기지 않고 토스트로 보여 줍니다.
46. 피해 적용과 부상(7판): 피해 굴림 결과의 "피해 적용"(GM만)에서 대상 시트와 방어구를 고르면 방어구를 뺀 값(최소 0)이 HP에서 빠지고, 시트의 "피해 입력"으로도 같은 규칙을 씁니다. 한 번에 받은 피해가 최대 HP의 절반 이상(홀수는 올림)이면 중상(`majorWound`)이고, 중상이 되면 본인과 GM에게 "건강 판정(CON)" 배너가 떠서 한 번에 CON으로 굴립니다. HP가 0이 되면 중상이 있을 때 빈사, 없을 때 기절이며, 피해가 최대 HP 이상이면 사망입니다(시트의 HP를 직접 고친 경우에는 즉사를 적용하지 않음). 회복은 GM이 "응급처치"(+1, 빈사가 풀림), "자연 회복"(+1), "직접 회복"으로 합니다. HP가 1 이상이 되면 빈사·기절이 풀리고 HP가 최대의 절반 이상이 되면 중상이 풀립니다. 사망은 회복으로 돌아오지 않고 GM이 상태를 직접 풀어야 합니다. 같은 피해 굴림은 같은 캐릭터에게 한 번만 적용합니다. 상태 칩(부상·중상·기절·빈사·사망)이 시트와 전투 순서에 보이고, NPC 시트는 PL에게 계속 "알 수 없는 상대"로만 보입니다. 서버 권한: PL은 자기 시트의 HP·MP·SAN·행운은 직접 바꿀 수 있지만(HP는 같은 규칙으로 상태가 맞춰짐), 기능 값, 무기, 상태 표시는 GM만 바꿉니다. 빈사 라운드 수는 전투에서 라운드가 한 바퀴 오를 때만 세고, "건강 판정에 실패하면 기절/사망"은 자동 처리하지 않고 GM이 표시합니다.
47. 굴림 식 엔진(`packages/shared/src/expr.ts`): `d100`, `1d6+1d4`, `2d6+6`, `(2d6+6)*5`, `3d6*5`, `1d10+db`처럼 `+ - * /`와 괄호, 주사위 항 여러 개를 쓸 수 있습니다. `eval` 없이 직접 읽으며 나눗셈은 내림이고 0으로 나누는 식은 거절합니다. 상한은 식 400자, 주사위 항 100개, 주사위 합계 1000개, 면 10000개, 괄호 깊이 8, 결과 10억입니다. 로그에는 항별 결과(`2d6[3,4]` 같은 내역)가 남고, 오류는 한글 문장으로 알려 줍니다. `db`는 시트의 피해 보너스(상수 또는 주사위)로 바뀌며, 시트가 둘 이상이면 굴림 칸에서 캐릭터를 고릅니다. 판정(`CC<=60`)의 푸시·행운 소비는 그대로 동작합니다.
48. 대항 판정: GM이나 PL이 "대항 판정"에서 두 시트와 기능을 고르면 두 굴림이 로그 한 항목에 결과 문장과 함께 남습니다(PL은 다른 PL 시트와만, NPC 시트와의 대항은 GM이 엽니다). 보너스·벌점 주사위, 푸시, 행운 소비는 없습니다. 성공 등급이 높은 쪽이 이기고(대성공 > 극단적 > 어려운 > 보통 > 실패, 대실패도 실패로 봄), 등급이 같으면 기능 값이 높은 쪽이 이기며 값이 같거나 둘 다 특성치로 굴렸으면 비깁니다(다시 굴림). 둘 다 실패하면 아무도 이기지 못하고 방어하는 쪽(맞서는 쪽)에 유리하게 상황이 이어집니다.
49. 그룹 판정: GM이 "판정 요청"에서 "그룹 판정"을 켜 보내면 PL 캐릭터들이 같은 기능으로 굴려 결과가 로그 한 항목의 요약("N명 중 M명이 성공했어요. 실패: ...")으로 남습니다. NPC 시트는 들어가지 않으며 비밀 굴림을 켜면 GM에게만 보입니다.
50. 시나리오 가져오기(웹): GM의 "설정 → 준비 → 시나리오 가져오기"에서 파일을 고르거나 글을 붙여 넣으면 먼저 미리 봅니다(장면·토큰·시트·핸드아웃·비트·음원 개수, 항목별 오류와 경고). 문제가 하나라도 있으면 가져오지 않고, 괜찮으면 지금 룸에 **더합니다**(지금 있는 것은 지우지 않으며, 비어 있는 첫 장면은 가져온 첫 장면으로 씁니다). 전부 한 번에 적용되거나 아무것도 안 됩니다. 적용 직후 토스트의 "되돌리기"(`scenario.revert`)로 방금 가져온 것만 지울 수 있습니다(룸당 마지막 한 번, 서버를 다시 켜면 사라짐). 파일은 웹소켓(16KB)이 아니라 HTTP `POST /rooms/:id/scenario`(룸 주인만, `?dryRun=1`은 검사만)로 가고 로그인 방식과 상관없이 같은 인증을 씁니다. 한 사람이 시간당 20번까지 가져올 수 있습니다. 형식(v2: 장면 `background`/`fog`, 토큰 `owner`/`image`/`vision`/`character`, NPC `luck`/`weapons`, 핸드아웃 `to`/`image`)은 `docs/scenario-format.md`, 파서는 `packages/shared/src/scenario.ts`이며 CLI(`--token`으로 운영 로그인도 가능)도 같은 파서를 씁니다. "예시 받기"로 문서와 같은 예시 파일을 받을 수 있습니다.
51. 장면 복제·순서: 장면 막대의 "복제"는 오브젝트·안개·배경·배경음을 "… 복사"로 원본 바로 뒤에 복사하고(복사본의 토큰은 시트 연결과 PL 소유를 잇지 않는 NPC 토큰), ◀ ▶ 는 순서를 바꿉니다. 이름 변경·삭제는 화면 안 대화상자입니다. 장면을 옮길 때 PL 토큰은 따라오고, 그 PL 토큰이 그 장면에서 마지막으로 있던 자리를 기억해 다시 오면 거기에 놓입니다. 처음 가는 장면에서는 **옮겨 오는 토큰의 지금 좌표를 그대로 쓰고 겹치면 가장 가까운 빈자리**에 놓습니다(보드 한가운데가 아니라).
52. 룸 관리: 룸 주인은 "설정 → 준비 → 룸 이름 바꾸기"로 이름을 바꾸고, "룸 내보내기 (백업)"으로 장면·오브젝트·핸드아웃·음원 참조·흐름·광기표·효과 설정을 JSON 하나(`roll-and-call-backup` v1, 이미지는 파일 안에 담음)로 받습니다. "시트 포함"을 켜면 시트도 담기며 복원하면 GM 소유 시트로 들어옵니다. 디스코드 웹훅·초대·접속한 사람의 id·이름은 담지 않고 GM 전용 노트는 GM 전용으로 남습니다. 로비의 "백업에서 새 룸 만들기"(템플릿 복사에도 씀)는 파일 검증 뒤 모든 id를 새로 매기고 이미지를 새 파일로 복사해 새 룸을 만들어서, 한 룸을 지워도 다른 룸의 이미지가 사라지지 않습니다. 오디오 파일은 담기지 않고 안내만 나옵니다. "시나리오 파일로 내보내기"는 같은 형식으로 시나리오만 받습니다.
53. 토큰↔시트 연결: GM이 토큰을 고르고 "시트 연결"에서 시트를 고르거나(시트 탭의 "토큰으로 놓기"는 연결해서 놓음) 풀 수 있습니다. 연결된 토큰은 아래에 얇은 HP 막대와 가장 무거운 상태 칩(부상·중상·기절·빈사·사망)을 보여 주고, HP·상태가 바뀌면 바로 따라갑니다. **PL에게는 자기 토큰과 자기 시트를 이은 토큰의 HP만** 가고, NPC 토큰의 HP는 GM이 "HP 공개"를 켜기 전에는 가지 않습니다(서버가 보내는 내용을 나눠 보내서, 화면에서만 숨기는 것이 아닙니다). 연결된 토큰을 끌지 않고 누르면 GM과 주인은 그 시트가 시트 탭에서 열립니다. 시트를 룸에서 빼면 그 시트를 이은 토큰의 연결이 풀리고 토큰은 남습니다. 토큰 복제는 연결을 잇지 않습니다.
54. NPC 시트: GM은 시트 탭의 "NPC 만들기"에서 이름과 HP·DEX·STR·SIZ·무기·방어구만 채우거나 "예시"(일반인·불량배·경찰관·광신도·사나운 짐승·괴물)를 골라 NPC 시트를 바로 만들고 "토큰도 같이 놓기"로 시트를 이은 토큰까지 놓습니다. HP는 입력한 값이 나오도록 CON을 맞추고(최대 19) 피해 보너스는 STR+SIZ로 정해지며, 방어구는 시트에 칸이 없어 메모에 "방어구 N"으로 적습니다(피해 적용 때 입력). 시트의 무기·기능 값은 GM만 직접 고치고 추가·삭제할 수 있고, 보관함에서 불러온 GM의 캐릭터도 NPC 시트가 됩니다. NPC 시트는 GM에게만 가고 피해·회복·상태 표시는 PL 시트와 똑같이 동작합니다.
55. 대화: 사이드 패널의 "대화" 탭(좁은 화면은 패널을 접어도 안 읽은 수가 탭과 "패널 펴기"에 보임)에서 룸 안 글 대화를 합니다. 한 번에 500자까지, 앞뒤 공백을 자르고 글로만 그립니다(HTML이 아님). Enter로 보내고 Shift+Enter는 줄바꿈이며, 한글 조합 중 Enter는 보내지 않습니다. "말하는 이름"에서 내 이름이나 내 캐릭터(GM은 "GM"이나 NPC 시트)를 고릅니다. 명령: `/r 식`·`/roll 식`은 주사위를 굴려 대화와 굴림 기록에 함께 남기고(세션 진행 중에만), `/hr 식`은 결과를 GM과 굴린 사람만 보고(대화에는 비밀 굴림, 굴림 기록에는 숨은 굴림으로 남음), `//`로 시작하면 슬래시를 하나 빼고 그대로 말하고, "?" 버튼이 명령 도움말을 보여 줍니다. 한 사람이 초당 3번까지(서버 룸 규칙, `tooMany("chat:"+userId)`)이고 그 위에서 연결 단위 속도 제한이 한 번 더 막습니다. 관전자는 GM이 "관전자 대화"(`settings.chat`의 `spectatorChat`, 기본 꺼짐)를 켰을 때만, 모두에게 보이는 말만 하고, 세션 시작 전·일시정지 중에도 대화는 되지만 굴림은 막힙니다. 아래로 붙어 있으면 따라 내려가고 위를 보는 중이면 "새 메시지" 버튼이 뜹니다. 대화는 룸과 함께 저장되어 마지막 500개만 남고, 접속하면 마지막 100개가 웹소켓으로 오되 **12KB 조각으로 나눠**(프레임 한도 16KB) 오며, 더 이전 대화는 "이전 대화 보기"가 HTTP `GET /rooms/:id/chat?before=&limit=`로 쪽 단위로 가져옵니다.
56. 귓속말: `/w 이름 내용`이나 "받는 사람" 목록으로 보냅니다(목록을 고르면 글은 슬래시 없이 그대로 귓속말). GM↔PL은 늘 되고, PL↔PL은 GM이 대화 탭의 "PL끼리 귓속말"(`settings.chat`, 기본 꺼짐)을 켰을 때만 됩니다. **서버가 보내는 쪽에서 거릅니다**: 귓속말은 보낸 사람과 받는 사람의 연결에만 가고(관전자·다른 PL에게는 프레임에도, 접속 때 받는 지난 대화에도, HTTP 쪽 불러오기에도 없음), 세션 기록·디스코드 알림에도 남지 않습니다. 결정: **GM도 자기가 보내거나 받은 귓속말만 봅니다** — PL끼리의 귓속말은 GM에게도 보이지 않고 그 사실을 설정 이름에서 알 수 있게 했습니다. `/w`의 이름은 사용자 이름(GM이 보면 PL의 캐릭터 이름도, PL이 보면 "GM"도)으로 찾고 같은 이름이 둘이면 목록에서 고르게 안내합니다.
57. 세션 기록과 내보내기: "기록" 탭은 세션 시작·일시정지·이어하기·종료(이유), 장면 전환, 핸드아웃 공개(제목만), 비트 이동, 전투 시작·끝·차례, 공개 굴림, 피해·회복·상처 상태, 광기·SAN 사건, 공개 대화만 구조화해 보여 줍니다(토큰 움직임은 기록하지 않음. 숨은 굴림과 귓속말은 기록 자체에 들어가지 않음). 룸과 함께 저장되며 최근 2000건까지 남습니다. GM은 전체(GM 전용 표시 포함), PL은 **자기가 볼 수 있는 항목만**(비트 이동·GM 전용 내용 제외, 안 보이는 NPC 이름은 가림, 남의 시트 피해는 제외, 공개되지 않은 핸드아웃 제외)을 서버가 걸러 받고, GM은 "참가자용으로 보기"로 PL이 볼 내용을 미리 볼 수 있습니다. 필터는 종류·세션·시작/끝 시각이며 `GET /rooms/:id/log?kinds=&since=&until=&session=&before=&limit=&view=public`(쪽 단위, 최대 500건)로 가져옵니다. "마크다운 저장"은 플레이 보고서 형식(세션·날짜 → 장면 구획, 진행 목록, 굴림 표, 핸드아웃 제목, 대화 발췌 인용)으로, "JSON 저장"은 같은 항목을 `coc-vtt-session-log` v1로 내려받습니다. 굴림 한 줄의 모양은 굴림 기록 저장과 같은 `rollRow`를 씁니다.
58. 저장 형식 번호: 룸 저장 데이터에 `schemaVersion`(지금 3; 번호가 없던 옛 데이터는 1)이 붙고, 읽을 때 `migrateRoomData()`가 빠진 대화·기록·설정을 기본값으로 채우며 모양이 깨진 대화·기록 한 줄은 버리고 모르는 필드는 그대로 둡니다(더 새로운 번호의 데이터도 아는 필드만 읽어 열림). 파일·Postgres(`rooms.data` jsonb)·메모리 저장소가 모두 룸 데이터를 통째로 저장하므로 DB 스키마 변경은 필요 없습니다. 옛 형식 고정 파일(`packages/room-core/src/fixtures/room-v1.json`)을 읽는 시험이 있습니다.
59. 보드 보기와 격자: 보기는 순수한 화면 변환(SVG viewBox)이라 서버 좌표는 그대로입니다. 확대는 최대 6배, 장면마다 사람마다 `localStorage`에 기억합니다(못 쓰면 그 화면에서만 유지). 토큰 이름표는 어두운 외곽선이 있어 확대·축소해도 11.5px 안팎으로 읽히고 토큰은 최소 약 34px, 눌리는 영역은 더 넓습니다. 장면 설정의 "격자"(GM, `scene.grid`: 한 칸 10~200, 보이기, 칸에 맞추기)는 기본이 꺼짐이며, 켜면 모두 격자를 보고 칸 맞춤이 켜진 장면에서는 끌어 놓은 토큰이 칸 가운데로 갑니다. "칸 맞춤" 버튼은 내 화면에서만 덮어쓰고, "자"는 두 점 사이 거리를 칸 수와 좌표 거리로 보여 주되 나에게만 보이며 저장하지 않습니다.
60. 키보드: "?"나 설정 메뉴의 "단축키 보기"가 단축키 도움말을 엽니다(PL에게는 GM 전용 키를 보여 주지 않음). 방향키는 토큰 하나를 20(칸 맞춤이 켜져 있으면 한 칸), Shift는 5 움직이며 주인과 GM만, 잠금·일시정지·세션 전에는 막힙니다. 토큰에는 `role="img"`와 이름·위치 설명이 붙습니다. 숫자 키 1~9는 연출 칸의 장면 전환인데, 세션 중에는 바로 바꾸지 않고 "장면 전환: 이름 · 3초 뒤" 알림이 뜨며 "취소"로 막을 수 있습니다. 지움·이동 되돌리기 알림에는 "되돌리기" 버튼이 있습니다.
61. 휴대폰(너비 640px 이하): GM은 아래 도구 묶음(접힘: "+ 토큰", "선택", 되돌리기, "패널"; 펼치면 놓기·안개·선택·연출 탭)을 쓰고 보드는 접힌 상태에서 화면의 55% 이상을 차지합니다. 알림은 아래 막대 위에 떠 "+ 토큰"을 가리지 않습니다. PL은 아래 막대("굴림·시트·핸드아웃·대화")가 옆 패널을 아래에서 올라오는 서랍으로 엽니다. 서랍이 닫혀 있으면 `inert`라 키보드가 들어가지 않습니다.
62. 태블릿(641~1024px): 옆 패널은 `clamp(280px, 34vw, 340px)`로 줄고, 놓기·안개 도구는 한 줄씩 쌓여 지도가 가려지거나 "+ 소품"·"+ GM 전용"이 잘리지 않습니다. 터치 화면(`pointer: coarse`)에서는 버튼·입력·탭이 44px 이상이고 "?" 도움말 버튼도 키우며, 1024px 이하 터치 화면의 글은 12px 이상입니다.
63. 룸 안 캐릭터 만들기: 시트 탭에서 아직 캐릭터가 없는 PL이 "캐릭터 만들기"를 누르면 보관함의 생성 마법사(`widgets/character-creator`)가 그대로 열리고, 끝내면 보관함에 저장한 뒤 그 캐릭터를 룸에 올립니다. 마법사 "다음"이 막히면 이유가 굵게 보이고, 나이 보정의 "교육 향상 판정" 버튼이 강조됩니다.
64. 토큰 상태 표식: 토큰마다 기절·중독·출혈·공포·광기·은신·집중·도움 필요·사망과 "사용자 지정"(글 8자까지) 표식을 켜고 끕니다(`object.marker`, 토큰당 10개까지). 표식마다 색·기호·모양(원/네모/알약)이 달라 색만으로 구분하지 않고, 토큰 둘레에 4개까지 배지로 그리고 넘치면 "+n"이며 각 배지에 `aria-label`("기절" 등)이 있습니다. 진입점은 GM의 선택 막대 "표식" 버튼과 오른쪽 클릭 메뉴의 "상태 표식"이고, PL은 자기 토큰을 골랐을 때 아래 표식 막대로 바꿉니다. **GM만 보임** 표식은 서버가 GM에게만 보내므로(`object.updated`·스냅샷·내보내기 모두) PL·관전자 화면과 프레임에 없고, 비밀 표식만 바뀐 경우는 리비전도 올리지 않아 PL이 변화를 알아챌 수 없습니다. 권한: GM은 모든 토큰, 주인 PL은 자기 토큰의 공개 표식만(비밀 표식이 걸린 종류를 PL이 누르면 아무 일도 없이 무시됩니다), 관전자는 불가. 되돌리기(Ctrl+Z)는 "표식 바꾸기"로 한 단계씩 되돌립니다. 시트의 부상 칩과 겹치지 않게, 시트가 이미 기절/사망 상태이면 같은 뜻의 표식 배지는 숨깁니다. 표식은 저장·백업·시나리오 내보내기(`markers`)에 들어가며 형식 번호가 올랐습니다(룸 저장 3, 시나리오 3, 백업 2; 옛 파일도 그대로 읽힘, 모르는 표식 키는 보존되고 "?"로 보임).
65. 관전 링크: 룸 주인이 초대 창의 "관전 링크 만들기"로 PL 초대와 별개의 링크(`kind: spectator`)를 만듭니다. 이 코드로 들어오면 늘 관전자이며 자리는 PL과 따로 셉니다(기본 10명, 만료·끄기 가능). 관전자가 받는 것은 보드·공개 굴림·모두에게 공개된 핸드아웃·모두에게 보이는 대화뿐이고, 시트·GM 노트·GM 전용 오브젝트·비밀 표식·귓속말은 프레임에도 가지 않습니다(관전자 소켓이 받는 모든 프레임 종류를 시험이 확인). 명령은 하나도 통하지 않으며(대화만 "관전자 대화"가 켜졌을 때 예외), 토큰 소유권도 받을 수 없습니다. 화면에는 "관전 중" 배지가 있고 편집 도구가 숨겨집니다. 주인은 초대 창에서 관전자 목록을 보고 "내보내기"(`member.remove`)로 내보낼 수 있으며, 내보내기는 차단이 아니라 연결 종료(코드 4410)이므로 같은 관전 링크로 다시 들어올 수 있습니다(막으려면 링크를 끄거나 새로 만드세요). 관전자 수는 GM에게만 보이고 PL의 접속자 목록에서는 빠집니다.

## 디스코드 로그인(Supabase) 연결

기본은 개발용 이름 로그인입니다. 아래 값을 주면 디스코드 로그인으로 바뀝니다(둘 다 없으면 개발용). 프로젝트 만들기, 디스코드 앱 등록, 리다이렉트 주소까지 단계별 설명은 [docs/deploy-env.md](docs/deploy-env.md)에 있습니다.

- API: `SUPABASE_URL` — 비대칭 서명 키(ES256/RS256) 프로젝트. `<SUPABASE_URL>/auth/v1/.well-known/jwks.json`의 공개키로 검증하고(캐시, 키 교체 때 자동 갱신, 시간 제한) `iss`·`aud`도 확인합니다.
- API: `SUPABASE_JWT_SECRET` — 레거시 공유 비밀(HS256) 프로젝트. 둘 다 주면 토큰 헤더의 `alg`로 고릅니다. 둘 중 하나라도 있으면 그 토큰만 받고 개발용 신원은 막습니다.
- Web: `NEXT_PUBLIC_SUPABASE_URL` — 로그인 버튼이 `/auth/v1/authorize?provider=discord`로 보내고 `/auth/callback`에서 토큰을 받습니다. Supabase 쪽 Redirect URL에 `<웹 주소>/auth/callback`을 등록해야 합니다. `NEXT_PUBLIC_SUPABASE_ANON_KEY`가 있으면 토큰이 만료됐을 때(룸 접속이 4401로 거절될 때, 로그인 상태를 불러올 때) 갱신 토큰으로 자동 갱신합니다.
- 실제 Supabase 프로젝트와 Discord 앱으로는 연결해 보지 못했습니다. 토큰 검증은 직접 생성한 키쌍과 가짜 JWKS 서버로 시험합니다(만료, 잘못된 aud/iss, alg=none, 모르는 kid, JWKS 장애 포함).

## 지금 한계

- 관전 링크로 들어온 사람을 개별로 차단하는 기능은 없습니다(내보내기는 연결 종료일 뿐). 표식은 열 가지 고정이며 사용자 지정은 토큰당 하나입니다.
- 인증은 기본이 개발용(이름만 입력)입니다. `NODE_ENV=production`에서는 Supabase 설정이 없으면 서버가 시작을 거부하지만, 디스코드 로그인과 JWKS 검증은 실제 Supabase 프로젝트로 확인하지 않았습니다(가짜 서버와 직접 만든 키로만 시험).
- **서버는 1대만 띄울 수 있습니다.** 룸의 실시간 상태가 서버 메모리에 있어서 여러 대로 늘리거나 무중단(블루/그린) 배포를 할 수 없습니다. 배포·재시작 때는 접속이 잠깐 끊겼다가 자동으로 다시 붙고, 갑자기 죽으면 마지막 저장 이후 약 0.5초의 변경을 잃을 수 있습니다. 서버를 늘리려면 룸을 서버에 고정하는 라우팅과 서버 간 중계가 필요합니다.
- Dockerfile은 만들었지만 이 환경에서는 도커 데몬이 없어 `docker build`를 돌려 보지 못했습니다(같은 명령을 빈 폴더에서 직접 돌려 확인). 실제 Fly·Render·Railway 배포, Supabase Postgres의 TLS 설정(`DATABASE_SSL`), Cloudflare R2 연결도 해 보지 못했습니다. 첫 배포 때 `deploy-env.md`의 출시 전 점검표를 따라 확인하세요.
- 디스코드 알림은 웹훅 한 방향입니다(봇·슬래시 명령은 없음). 대화·귓속말은 디스코드로 보내지 않습니다.
- 대화는 한 번에 500자·마지막 500개, 세션 기록은 최근 2000건까지만 남고 오래된 것부터 사라집니다(내보내기로 따로 보관). 대화는 글만 지원하고 이미지·멘션·수정·삭제는 없으며, 기록 내보내기는 이 브라우저에서 만들어 받습니다(한 번에 최대 약 1만 건).
- 저장소: 개발 기본은 파일이고 `DATABASE_URL`을 주면 Postgres(스키마는 서버가 만들며 `deploy/schema.sql`과 같음)입니다. 번호가 붙은 마이그레이션 도구는 없어서 컬럼 삭제·타입 변경 같은 변경은 아직 손으로 해야 합니다. 이미지는 `S3_BUCKET`을 주면 R2/S3, 아니면 DB(bytea)·파일입니다. 저장소를 바꿀 때 기존 파일을 옮겨 주는 도구는 없습니다. 이미지는 API가 읽어서 돌려주므로 버킷을 공개할 필요는 없지만, 그만큼 API 트래픽을 지납니다.
- 쓰이지 않는 이미지 정리(`cleanup:images`)는 스케줄러가 아니라 손으로(또는 호스트의 cron으로) 돌립니다. 룸을 가리키는 id만 보며, 보관함·서재가 이미지를 가리키게 되면 그 검사도 넣어야 합니다.
- 서버 로그는 JSON 한 줄이고 비밀 값은 가리지만, 로그 수집·알림·지표(예: Sentry, Prometheus)는 붙어 있지 않습니다. `/health`의 `status`를 외부 모니터로 보세요. 웹 화면의 오류도 서버로 보내지 않습니다(브라우저 콘솔에만 남음).
- 웹에는 전체 CSP(`script-src` 등)가 없고 `frame-ancestors`·`nosniff` 등 일부 보안 헤더만 있습니다. CORS는 `WEB_ORIGIN` 한 주소만 허용해서 Vercel 미리보기 배포에서는 API를 부를 수 없습니다.
- 보드 확대·격자·자는 화면 변환일 뿐 서버 좌표는 정수 그대로이고, 자(거리 재기)는 저장·공유하지 않으며 격자는 장면당 하나의 정사각 격자뿐입니다(육각형·등각 격자 없음). 두 손가락 돌리기(회전)는 없습니다.
- 보드는 SVG입니다. 명세의 react-konva로 바꾸는 일은 보드 컴포넌트 안에서 끝납니다.
- 시나리오 가져오기는 룸당 마지막 한 번만 되돌릴 수 있고(서버를 다시 켜면 사라짐) 파일 크기는 64MB까지입니다. 장면·오브젝트·시트·핸드아웃 수에는 룸 한도(장면 30, 오브젝트 500, 시트 30, 핸드아웃 100)가 그대로 적용됩니다. 백업에는 오디오 파일이 담기지 않고, 시트는 주인이 아닌 GM 소유로 복원됩니다. 장면에 "시작 위치"나 장면 메모는 없어서 복제는 오브젝트·안개·배경·배경음만 복사합니다.
