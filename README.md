# CoC 7판 VTT (개발 중)

명세: Claude Docs "CoC 7판 VTT 서비스 명세서". 지금은 실시간 뼈대, 룸 생성·초대·세션 흐름, 파일 저장까지 구현했습니다.

## 구조

모노레포(pnpm)이고, 프런트는 FSD, 백엔드는 DDD로 나눕니다. 의존 방향은 `pnpm arch`가 검사합니다.

| 경로 | 역할 |
| --- | --- |
| `apps/web` | Next.js 프런트엔드(FSD). `src/app`(라우트, 얇게) → `views` → `widgets` → `features` → `entities` → `shared`. 위 계층만 아래를 가져오고, 다른 슬라이스는 `index.ts`로만 접근 |
| `apps/api` | NestJS 백엔드(DDD). 컨텍스트 `identity`(신원), `room`(룸·초대·실시간), `character`(보관함). 각 컨텍스트는 `domain` ← `application` ← `infrastructure`/`interface`. 구성 루트는 `app.module.ts` |
| `packages/room-core` | 룸 엔진(권한, 보임 범위, 굴림, 시트, 재접속, 일시정지). 네트워크를 모르는 순수 도메인 로직 |
| `packages/shared` | 메시지 규격(zod), 주사위 엔진(BCDice 7판 표기), 시트 모델, 클라이언트 상태 리듀서 |

## 실행

```bash
pnpm install
pnpm dev:api     # http://localhost:8787 (ws: /ws)
pnpm dev:web     # http://localhost:3000
pnpm test        # 단위·통합 테스트
pnpm arch        # 아키텍처 의존 방향 검사
pnpm e2e         # 실제 브라우저 여러 개로 전체 흐름 확인(위 두 서버가 떠 있어야 함)
```

## 흐름

1. 로비에서 이름으로 로그인(개발용) → 새 룸을 만들면 만든 사람이 KP가 됩니다.
2. KP가 룸 안의 "초대"로 링크를 만들어 PL에게 보냅니다. 초대 코드가 없으면 처음 오는 사람은 들어올 수 없습니다.
3. 룸은 "대기(IDLE)"에서 시작합니다. KP만 준비할 수 있고, "세션 시작"을 누르면 진행 중이 됩니다.
4. KP는 맵을 "장면"으로 나눠 미리 꾸밀 수 있고(PL에게는 진행 중인 장면만 보임), 컷/페이드로 전환합니다. 핸드아웃은 선택한 PL에게 공개하고 바로 펼쳐 보일 수 있습니다.
5. KP가 나가면 자동 일시정지, 돌아와서 "이어하기"를 누르면 재개합니다. "세션 종료"는 대기로 돌아갑니다.
6. 캐릭터는 로비의 "내 캐릭터"(보관함)에서 만듭니다. 룸의 "시트" 탭에서 불러오면 복사본이 생기고, 시트는 주인과 KP만 봅니다. 세션이 끝나면 "보관함에 반영"으로 HP·SAN·기능·성장 표시를 원본에 되돌립니다.
7. 룸 상태는 `apps/api/data/`에 JSON으로 저장되고 서버를 다시 켜도 이어집니다(진행 중이던 세션은 일시정지로 복원). `DATA_DIR=memory`로 끌 수 있습니다.
8. 세션 종료는 정산 창을 거칩니다. KP가 엔딩 이름, SAN 보상 식(예: 1d6)을 정하고, 성장 표시가 된 기능은 성장 굴림(d100이 현재값보다 크거나 96 이상이면 +1d10)을 합니다. 결과는 모두에게 보입니다.
9. 시트의 "SAN 체크"에 `성공 시/실패 시`(예: 0/1d6)로 손실을 적어 굴립니다. 대실패는 실패 손실의 최댓값, 한 번에 5 이상 잃으면 INT 판정(성공 시 일시적 광기), 하루 손실이 하루 시작 SAN의 1/5 이상이면 장기 광기, SAN 0은 영구 광기로 시트에 표시합니다. "하루 지남"은 KP가 누릅니다. 광기 상태는 KP만 바꾸고, KP가 적어 둔 "광기표"에서 증상과 지속 시간을 굴립니다(증상표는 KP에게만 보이고, 룰북 표는 담지 않았습니다).
10. KP는 룸 안의 "디스코드"에서 채널 웹훅을 연결하면 세션 시작·정지·종료와 공개 굴림이 채널에 올라갑니다(비밀 굴림은 보내지 않고, 웹훅 주소는 저장 뒤 다시 보여 주지 않습니다).
11. 시트에는 무기(공격 기능·피해 식), 소지품, 인물 배경, 상태(중상·기절·죽어감)가 있습니다. 무기의 "공격"은 그 기능으로 판정하고 "피해"는 `1d6+db`처럼 적은 식을 굴려 로그에 남깁니다(db는 STR+SIZ로 계산한 피해 보너스). 상태 표시는 자동 판정과 연결하지 않았습니다.
12. 이미지: KP는 선택한 토큰·소품에 "이미지", 장면 막대에서 "배경", 핸드아웃 편집에서 "이미지 넣기"로 PNG/JPG/GIF/WEBP(3MB까지)를 올립니다. 서버는 파일 앞부분으로 형식을 확인하고(SVG는 받지 않음), 사람마다 시간당 30장으로 제한합니다. 개발 기본값은 `data/images` 폴더에 저장하고, 저장소는 `ImageStorage` 포트라서 R2/S3 어댑터로 바꿀 수 있습니다. 이미지 주소는 추측할 수 없는 id라서 보기는 로그인 없이 열리고, 쓰지 않는 파일을 지우는 정리는 아직 없습니다.
13. 시작 장면: KP가 장면 막대에서 "시작 장면으로"를 누르면 ▶ 표시가 붙고, 다음 세션을 시작할 때 그 장면이 컷으로 열립니다. 지정은 KP만 보고 하나만 남습니다. 비트·분기 같은 나머지 세션 흐름은 아직 없습니다.
14. 전투 순서: 룸의 "전투" 탭에서 KP가 "전투 시작"을 누르면 룸의 캐릭터가 시트 DEX 높은 순으로 서고(같은 DEX는 먼저 등록한 쪽이 앞), NPC는 이름과 DEX로 끼워 넣습니다. "다음 차례"로 넘기고 한 바퀴 돌면 라운드가 오르며, 모두가 같은 순서를 봅니다(캐릭터 DEX도 함께 보입니다). 행동 순서 외의 전투 자동화(명중·피해 적용, 총기 DEX +50 등)는 하지 않습니다.
15. 저장소: 개발 기본값은 `data/` 폴더의 파일이고, `DATABASE_URL=postgres://...`를 주면 룸·보관함·이미지를 Postgres에 저장합니다(Supabase의 Postgres 주소도 같은 방식). 서버가 켜질 때 테이블이 없으면 만들며(`rooms`, `vaults`, `libraries`, `images`), 서버를 다시 켜도 룸과 이미지가 남는 것을 로컬 Postgres 16으로 확인했습니다. 어댑터 테스트는 `TEST_DATABASE_URL=postgres://... pnpm test`로 켭니다(없으면 건너뜁니다). 실제 Supabase 연결은 하지 않았고, 이미지는 bytea로 저장하므로 트래픽이 커지면 R2/S3 어댑터로 바꿉니다.
16. 세션 흐름(KP 전용 "흐름" 탭): 시나리오를 비트(시작·진행·엔딩)로 짜고, 비트마다 들어갈 때 열 장면과 펼칠 핸드아웃(큐), KP 메모를 정합니다. 비트 사이의 분기는 수동, 판정 결과(기능+단계), 수치 임계(HP·SAN·행운), 핸드아웃 공개 조건을 둘 수 있고, 조건이 맞으면 서버가 KP에게만 "제안"합니다(스스로 옮기지 않고, KP의 비밀 굴림은 쓰지 않습니다). 세션을 시작하면 시작 비트의 큐가 실행되고, 엔딩을 확정하면 종료 창이 엔딩 이름과 SAN 보상으로 미리 채워집니다. 비트별 "자동 실행"은 만들지 않았습니다(기본 꺼짐 상태와 같습니다).
17. 음향(KP 전용 "음향" 탭): KP가 mp3/ogg/wav/m4a(10MB까지)를 배경음(반복) 또는 효과음(한 번)으로 올려 라이브러리에 두고, 재생·정지·볼륨·페이드(없음/1초/3초)를 조절합니다. 소리는 서버가 알려 준 시작 시각 기준으로 모두 같은 자리에서 흐르고(배경음은 늦게 들어와도 지금 소절부터), 참가자는 헤더의 "소리"에서 배경음·효과음·굴림 효과음 볼륨과 전체 음소거를 이 브라우저에 저장해 따로 조절합니다. 굴림 효과음은 파일 없이 합성한 짧은 소리입니다. 음원 이름은 KP만 보고 참가자는 파일 id만 받습니다. 비트 편집의 "들어갈 때 틀 배경음"으로 비트 큐에 묶을 수 있고, 음원을 지우면 연결도 풀립니다. 브라우저 정책상 첫 클릭·키 입력 뒤에야 소리가 나며(헤더 "소리 켜기"로도 가능), 실제 소리는 자동 테스트로 확인하지 못해 재생 상태(DOM)만 검증했습니다. 업로드한 음원 정리와 로컬 파일 외 저장소 어댑터(R2 등)는 이미지와 같은 상태입니다.
18. 장면 묶음: 장면 막대의 "장면 배경음"으로 장면에 라이브러리의 배경음을 묶으면, 그 장면으로 바뀔 때(수동 전환·시작 장면·비트 큐 모두) 함께 틀립니다. 페이드 전환이면 1.5초 페이드이고, 이미 같은 곡이 흐르고 있으면 끊지 않습니다. 맵(배경)·오브젝트 배치·전환 효과(컷/페이드)는 기존 장면 기능을 그대로 쓰며, 배경음 연결은 KP만 알고 음원을 지우면 풀립니다. 전환 효과를 장면에 미리 묶어 두는 것은 하지 않았습니다(전환할 때 컷/페이드를 고릅니다).
19. 로그 내보내기: 룸의 "굴림" 탭에서 "굴림 기록 저장"을 누르면 세션별로 묶은 굴림 기록(시각·이름·캐릭터/기능·식·결과, 비밀·푸시·행운 표시)이 마크다운 파일로 내려옵니다. 서버를 거치지 않고 이 화면이 이미 받은 기록으로 만들기 때문에, 보는 사람이 볼 수 없던 굴림(PL 화면의 KP 비밀 굴림)은 담기지 않고 그 안내가 붙습니다. 화면에는 최근 200건까지만 남아 있어 그보다 오래된 굴림은 파일에도 없으며, 채팅·핸드아웃·시트 변경 이력은 포함하지 않습니다.
20. 매크로: "굴림" 탭의 "매크로 편집"에서 이름과 굴림 식(`1d6+2`, `CC<=60` 등)을 저장해 두면 버튼 한 번으로 굴립니다. 식은 저장할 때 서버와 같은 규칙으로 미리 확인하고(잘못된 식은 거절), 이름은 20자·개수는 12개까지, 같은 이름은 둘 수 없습니다. KP는 "비밀 굴림으로 굴리기"를 켠 매크로(🔒)를 만들 수 있습니다. 매크로는 사람마다 따로 서버의 "내 서재"에 저장되어 기기를 옮겨도 따라옵니다(23번). 시트 기능 판정은 시트의 굴림 버튼을 그대로 씁니다.
21. 생성 마법사: 내 캐릭터의 "마법사로 만들기"가 7판 규칙대로 네 단계(기본 정보 → 특성치 → 기능 → 확인)로 안내합니다. 특성치는 굴리거나 직접 적고(합계 안내, 포인트 구입은 460), 나이 보정을 적용합니다(15~19세: STR·SIZ 합계 −5·EDU −5·행운 두 번 굴려 높은 쪽 / 40대 이후: STR·CON·DEX에서 −5·−10·−20·−40·−80을 직접 나눠 깎고 APP·교육 향상 판정 횟수도 나이대별로 적용). 교육 향상 판정은 d100이 EDU보다 클 때 1d10을 올립니다. 기능은 직업 포인트(EDU×4 또는 EDU×2+STR/DEX/APP/POW×2 중 선택)와 관심 포인트(INT×2)를 따로 쓰며, 한 기능은 75까지·남는 포인트는 그대로 둘 수 있고, 모국어·크툴루 신화에는 쓸 수 없습니다. 기본 기능에 신용도(0)를 더했습니다. 직업은 이름만 적고 직업별 기능 목록·신용도 범위·직업 포인트 공식은 정해 두지 않았으며(직업 정의는 사용자가 직접 만드는 방침), 기능은 직업 포인트로 쓸 수 있는 목록을 제한하지 않습니다. 기존 "새 캐릭터" 폼은 그대로 있어 만든 뒤 무기·세부를 고칠 수 있습니다.
22. 직업 정의: 내 캐릭터 화면의 "직업 정의하기"에서 직업 이름, 직업 포인트 공식, 신용도 범위(0~99), 직업 기능(12개까지, 신용도는 늘 포함)을 저장해 두면 생성 마법사 첫 단계에서 불러 쓸 수 있습니다. 불러오면 직업 포인트는 직업 기능(★)과 신용도에만 쓸 수 있고 신용도(직업+관심 포인트 합)는 정한 범위 안이어야 다음 단계로 넘어갑니다. 안 고르면 제한이 없습니다. 직업 정의는 사람마다 따로 서버의 "내 서재"에 저장하고(23번), 20개까지, 같은 이름은 둘 수 없습니다. 기본 직업 목록은 넣지 않았습니다(직업 정의는 사용자가 직접 만드는 방침). 대신 정의를 고치고(수정), 파일(JSON)로 내보내고 가져와 KP와 PL이 직업 목록을 나눌 수 있습니다(가져올 때 규칙에 안 맞거나 이름이 겹치는 직업은 건너뜁니다). 마법사 규칙 계산은 `packages/shared/src/creation.ts`에 있어 서버 저장으로 옮길 때 그대로 쓸 수 있습니다.
23. 내 서재(서버 저장): 굴림 매크로와 직업 정의는 `GET/PUT /library`로 서버에 사람별 한 덩어리로 저장합니다(파일은 `data/library`, Postgres는 `libraries` 테이블, 로컬 Postgres 16으로 어댑터 확인). 서버가 매크로 12개·직업 20개·이름 중복·굴림 식·직업 정의 규칙을 다시 검사하고, 저장은 통째로 바꾸되 저장 번호(revision)를 함께 보내, 그 사이 다른 기기가 저장했으면 서버가 409와 최신 서재를 돌려주고 화면이 항목(id) 단위로 합쳐 다시 저장합니다(같은 항목을 둘 다 고쳤으면 내 쪽이 이기고, 이름 중복·개수 한도 때문에 합칠 수 없으면 최신 내용을 불러오고 알립니다). 창으로 돌아올 때도 다른 기기의 변경을 가져옵니다. 화면은 서버에서 불러온 뒤에만 고칠 수 있고(불러오기 전에 빈 값으로 덮어쓰지 않도록), 저장에 실패하면 화면을 되돌리고 알립니다. 이전에 이 브라우저에 저장해 둔 매크로·직업은 서버 서재가 비어 있을 때 처음 접속하면서 한 번 옮기고 브라우저 쪽은 지웁니다.
24. 안개와 시야: KP가 보드 아래 "안개 켜기"를 누르면 그 장면에서 참가자(PL·관전자)에게는 원 밖이 검게 가려집니다. 원은 "영역 밝히기"(반지름을 고르고 보드를 눌러 찍음, 장면당 60개까지, 되돌리기·모두 지우기)와 토큰의 "시야 주기"(반지름 10~600, 토큰이 움직이면 같이 움직임)로 만들며, 모든 참가자가 같은 원을 봅니다(파티 시야). 원 밖의 오브젝트는 서버가 그 사람에게 아예 보내지 않고(움직이거나 시야가 바뀌면 새로 보내거나 지움), 내 토큰은 항상 보이며 GM 전용 오브젝트는 원 안에서도 안 보입니다. KP 화면에는 가려진 곳이 반투명하게 보이고 원 테두리가 점선으로 나옵니다. 지도 배경도 안개에 가려집니다. 벽·조명에 따른 시야 계산은 하지 않았고(원형 반지름만), 한 번 밝힌 곳을 기억해 두는 탐험 기록도 없습니다. 시야 토큰이 숨겨진 상태여도(GM 전용) 그 둘레는 밝아지므로 필요하면 시야를 주지 마세요.

## 디스코드 로그인(Supabase) 연결

기본은 개발용 이름 로그인입니다. 아래 값을 주면 디스코드 로그인으로 바뀝니다(둘 다 없으면 개발용).

- API: `SUPABASE_JWT_SECRET` — Supabase의 JWT Secret(HS256). 설정하면 이 토큰만 받고 개발용 신원은 막습니다.
- Web: `NEXT_PUBLIC_SUPABASE_URL` — 로그인 버튼이 `/auth/v1/authorize?provider=discord`로 보내고 `/auth/callback`에서 토큰을 받습니다. Supabase 쪽 Redirect URL에 `<웹 주소>/auth/callback`을 등록해야 합니다.
- 아직 로컬 개발만 하므로 실제 연결은 해 보지 않았습니다. 토큰 검증은 직접 서명한 토큰으로 테스트합니다. 토큰 자동 갱신은 없고(만료되면 다시 로그인), 비대칭 키(JWKS)를 쓰는 프로젝트는 검증기를 바꿔야 합니다.

## 지금 한계

- 인증은 기본이 개발용(이름만 입력)입니다. 디스코드 로그인은 연결 구조만 있고 실제 Supabase 프로젝트로는 확인하지 않았습니다.
- 디스코드 알림은 웹훅 한 방향입니다(봇·슬래시 명령은 없음).
- 저장소는 파일입니다. Postgres 어댑터는 `RoomStore` 인터페이스 뒤에 붙일 예정입니다.
- 보드는 SVG입니다. 명세의 react-konva로 바꾸는 일은 보드 컴포넌트 안에서 끝납니다.
- API는 `tsx`로 실행합니다. 배포용 빌드(번들링)는 아직 없습니다.
25. 안개 탐험 기록: 안개가 켜진 장면에서 시야 토큰·밝힌 영역이 한 번이라도 비춘 자리를 서버가 장면마다 기록해 두고(최대 200개, 거의 겹치는 원은 합침, 밝힌 영역을 지워도 남음) PL에게는 지금 안 보이지만 가 본 자리를 어둡게 비춰 보여 줍니다. 그 자리의 오브젝트는 지금 시야 밖이면 여전히 보내지 않습니다. KP 화면에는 기록이 점선 고리로 보이고 "탐험 기록 지우기"로 비울 수 있습니다.
26. 시나리오 가져오기: `pnpm import:scenario <시나리오.json> [--user 이름] [--api 주소] [--room 룸이름]`이 시나리오 파일(`format: roll-and-call-scenario`)을 KP가 만든 것처럼 룸 하나로 옮깁니다(장면·시작 장면, 소품·NPC 토큰, NPC 시트, 핸드아웃, 세션 흐름의 비트·분기). 서버가 켜져 있어야 하고, 개발용 로그인은 이름이 곧 신원이라 같은 이름으로 로비에 들어가면 "내 룸"에 보입니다. 시나리오 파일 자체는 저장소에 넣지 않습니다.

받은 뒤 화면이 `Module not found`로 깨지면 새 패키지(폰트)가 설치되지 않은 것이니 `pnpm install`을 먼저 실행하세요.
27. 화면 정리(밤의 탁자): Linear·Cursor 계열의 낮은 대비·얇은 선·작은 글자로 디자인 토큰을 다시 잡았습니다(`apps/web/src/app/globals.css`). 버튼이 흩어져 있던 곳은 메뉴로 접었습니다: 룸 헤더는 "초대"와 "세션 시작"만 밖에 두고 효과·소리·판정 효과·광기표·디스코드는 "설정" 메뉴로, 장면 막대의 시작 장면·배경·배경음·이름·삭제는 "장면 설정" 메뉴로 모았습니다. 보드 아래 도구에는 "놓기·안개·단축키" 이름표와 설명(마우스를 올리면 보임)을 달았고, KP가 세션 시작 전에 룸에 들어오면 "장면 꾸미기 → 토큰 놓기 → PL 부르기 → 세션 시작" 체크리스트가 보이며 끝낸 단계는 자동으로 체크됩니다.
28. KP 전용 노트: 핸드아웃을 "KP 전용 노트"로 만들면 공개 범위를 바꾸거나 펼쳐 보이거나 비트·분기 조건에 붙일 수 없어 실수로 PL에게 새지 않습니다(서버가 거절). 노트를 일반 초안으로 되돌리려면 편집에서 공개 범위를 바꿉니다. 시나리오 가져오기는 제목이 `[KP]`로 시작하는 핸드아웃을 노트로 만듭니다.
29. 룸 삭제: 로비 카드의 "삭제"를 누르고 한 번 더 확인하면 룸 주인이 룸을 지웁니다(`DELETE /rooms/:id`, 주인만). 저장소에서 지우고 붙어 있던 연결은 4404로 끊기며, 대기 중이던 저장이 룸을 되살리지 않습니다. 되돌릴 수 없습니다.
